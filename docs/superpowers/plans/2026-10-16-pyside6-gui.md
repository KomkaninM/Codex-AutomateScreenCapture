# PySide6 GUI Implementation Plan

> Execute inline using superpowers:executing-plans. Use test-driven development and verification-before-completion.

**Goal:** Migrate the complete desktop interface to PySide6 while preserving the automation system and legacy rollback.

**Architecture:** Qt pages consume existing ProjectStore and ProcessController APIs. QThread jobs and a batched signal bridge isolate blocking work. A frozen role dispatcher reuses the existing automation entry points.

**Tech Stack:** Python 3.11–3.14, PySide6 6.10.2, unittest, optional PyInstaller.

**Spec:** ../specs/2026-10-16-pyside6-gui-design.md

## Global constraints

Only feat/pyside6-gui; no push/merge. Keep Tkinter files. Preserve .env values, JSON schemas, LINE commands/messages, scheduling and automation. Tests must not access live BMS/LINE.

## Review focus

- A slow or invalid macro must not block navigation or crash a refresh.
- Closing during a pending launch or save must keep workers alive until cleanup.
- External settings changed through LINE must reject stale GUI saves.
- Frozen child roles must execute automation rather than recursively opening windows.
- A read-only installation folder must not be used for writable operator files.

## Verification record

- Full safe suite: `XDG_CACHE_HOME=/tmp/bms-qt-cache .venv/bin/python -m unittest discover -s tests -q` — **248 tests, 233 passed, 15 skipped** on Python 3.12. Skips cover legacy Tk desktop widgets and actual Windows file sharing. Localhost socket tests require the execution sandbox's socket permission; they pass when allowed. No live BMS/LINE traffic was used.
- New Qt coverage: 18 offscreen tests, including application-thread callbacks, process-lock responsiveness, dirty/stale forms, macro/anchor imports, LINE notification formatting, safe restart/Stop races, log bounds and active-work shutdown.
- Runtime coverage: 6 tests for public-default seeding, source/frozen role commands, data paths, internal dispatch and actionable startup errors. Existing launcher/controller tests were extended.
- Actual `app_entry.main` smoke runs from `/tmp` with temporary operator data: all five pages captured, normal and 1.5 Qt scale factors, exit code 0 after cooperative close. Visual inspection covered Dashboard, Settings, Targets, Macros and Help. This does not establish real Windows drag/DPI behavior.
- Ruff static checks (E4/E7/E9/F/I) and formatting pass for all new Python files. All 39 project Python files and the packaging spec compile. `pip check` and `git diff --check` pass.
- Original Tkinter files and automation/LINE/scheduler/macro/capture implementations match origin/main byte-for-byte. No files were removed and no existing .env values were edited.

## Review and fixes

An independent read-only code review identified four material issues. Each was reproduced before its fix and verified with a regression test:

- Controller launch lock could block Qt: `test_gui_never_waits_for_process_launch_lock` now confirms GUI controls read published state without acquiring that lock.
- Malformed macro recursion/numeric overflow could disable setup: `test_malformed_macros_do_not_disable_settings_or_refresh` confirms catalog/readiness mark those files as needing repair.
- External data confused bootstrap paths: `test_gui_bootstrap_keeps_code_root_separate_from_external_data` confirms dependency/code paths stay in source while data is initialized separately.
- Minimum-size controls collapsed: `test_minimum_window_keeps_macro_and_target_controls_readable` confirms scrolling preserves control heights.

Additional regression tests pin Stop during validation, retry after failed local stop-file writes, and close during launch/save. No material review findings remain unresolved.
